(async) conn() → {Promise}

Description:

  • 連線至FPT伺服器

    連線可用(FTP為收到伺服器歡迎訊息220，SFTP為完成連線並開啟SFTP通道)才resolve，並以WFtp之opt.timeLimit計時；連不上時以固定訊息reject(ftpConn: can not connect to the server (<code>)，逾時為ftpConn timeout[timeLimit])，不會造成未捕捉例外，為Node錯誤碼、FTP回應碼或'AUTHENTICATION'、'HANDSHAKE_TIMEOUT'、'CLOSED'、'UNKNOWN'。conn尚未完成即呼叫之操作會等待其完成；conn失敗後實例視為未連線(quit仍可呼叫)。 連線建立後之中斷與重新連線見README之Connection behavior。conn會重設以cwd切換之工作資料夾。

(async) cwd() → {Promise}

Description:

  • 伺服器變更工作路徑資料夾

    FTP送出CWD指令並回傳伺服器回應，成功之cwd於重新連線時依序重放，無法重放時reject(須重新conn)。 SFTP協定無工作資料夾，由本套件保存：目標存在且為資料夾時resolve其絕對路徑字串，其後各操作之相對路徑以其解析；目標不存在或非資料夾時reject(ftpCwd: can not change the working directory, fpRemote is not a folder)。conn重設工作資料夾。 以WFtp之opt.timeLimit計時，到時reject並銷毀本次所用之連線。

(async) download() → {Promise}

Description:

  • 下載伺服器指定檔案至本機

    先寫入下載暫存區(opt.fdDownloadTemp)內本次專用之暫存檔(<檔名>.<行程id>.<隨機碼>.part，以排他方式建立，同一暫存區由多個實例共用或遠端檔名相同皆不相撞)， 傳輸成功結束且本地大小等於遠端大小才移至fpLocal(取代舊檔)；與fpLocal同一磁碟時以改名一步取代，跨磁碟時先複製至fpLocal同資料夾之暫存名(<檔名>.<行程id>.<隨機碼>.part)再於同資料夾內改名；檔名超過150位元組者，暫存名中之檔名基底以碼點截短(使暫存名不超過255位元組)； 遠端大小無法取得(FTP之SIZE指令失敗)時無從核對是否下載完整，直接reject(can not get the size of file[fpRemote])而不傳輸；fpLocal為既有資料夾時於傳輸前即reject(ftpDownload: fpLocal is a directory, fpLocal is not changed)；改名遇占用(EPERM、EBUSY、EACCES，Windows下常為防毒掃描)時最多嘗試5次(每次失敗後等待200毫秒乘嘗試次數)，用盡仍失敗即刪除暫存檔並reject。 暫存區內逾24小時未更新、符合上述暫存檔名格式、行程id對應之行程已不存在者(本行程與他行程仍存在者皆不清)，視為崩潰殘留，由本行程於首次使用該暫存區時清除(之後同一行程最多每小時清一次)；不符格式之檔不動。 傳輸失敗(含連線中斷)、逾時、大小不符或無法移動時，刪除暫存檔並reject，fpLocal之舊檔不動(不存在者仍不存在)。 逾時自傳輸開始起計(WFtp之opt.timeLimit，預設60000毫秒，SFTP亦受其約束，大檔須自行給較大值)，到時即reject(訊息ftpDownload timeout[timeLimit])並刪除暫存檔名；查詢遠端檔案資訊之階段另受同一timeLimit約束，伺服器於該階段停滯時同樣逾時。逾時時銷毀本次所用之連線(FTP含數據socket；SFTP以此中止fastGet)，同一連線上同時進行之其他操作一併失敗；下一個操作自動重新連線，故逾時後可直接重試同一檔(暫存檔名每次唯一)。

(async) downloadViaTemp(o) → {Promise}

Description:

  • 下載單一檔案之共用流程(SFTP與FTP共用, 單一擁有者): 先寫入暫存區之本次專用暫存檔, 傳輸成功結束且本地大小等於遠端大小才移至fpLocal; 失敗、逾時、大小不符皆刪除暫存檔並reject, fpLocal之舊檔不動

    逾時: 自傳輸開始起計時timeLimit毫秒, 到時即reject(ftpDownload timeout[timeLimit]), 並呼叫傳輸端登記之中止函數(FTP為銷毀數據socket; SFTP無法中止, 傳輸可能於背景續行), 其後傳輸結束時一律只刪暫存檔、不移至fpLocal; 暫存檔名每次唯一, 故逾時後重試同一檔不與背景傳輸相撞

    opt.onTrace事件(type): 'sweep'({ removed })、'temp'({ act: 'create'|'remove', ok })、'timeout'({ timeLimit, stage })、'transfer'({ ok, late })、'verify'({ ok, size, sizeRemote })、'retry'({ n, code })、'move'({ mode: 'rename'|'copy' }); 逾時後之'transfer'(late為true)與'temp'(act為'remove')於promise已reject後才發生, 供得知背景傳輸已結束且暫存檔已清

(async) upload() → {Promise}

Description:

  • 上傳本機指定檔案至伺服器

    先寫入遠端目標同一資料夾之本次專用暫存名(<檔名>.<行程id>.<8碼隨機碼>.part，檔名超過150位元組者基底以碼點截短)，傳輸成功結束且遠端暫存大小等於本機大小(本機大小於傳輸期間亦未改變)才改名為fpRemote； 傳輸失敗(含連線中斷)、逾時、大小不符、本機檔改變或改名失敗時，刪除遠端暫存並reject，fpRemote之舊檔不動。FTP以串流讀本機檔(不整檔讀入記憶體)，不改變工作目錄；多層資料夾自動建立。

    改名：SFTP用posix-rename@openssh.com擴充覆蓋(原子)，伺服器未支援或拒絕時改用一般rename；FTP用RNFR/RNTO。伺服器之rename不覆蓋既有檔時(部分FTP伺服器、無該擴充之SFTP伺服器)，改依序「舊檔改為暫存名(<檔名>.<行程id>.<隨機碼>.old)、暫存改為fpRemote、刪除舊檔暫名」，此時非原子(兩次改名之間fpRemote不存在)，中途失敗會嘗試把舊檔改回。 伺服器須允許改名與刪除；不允許改名者reject(ftpUpload: can not rename the temporary file to fpRemote (<code>), fpRemote is not changed)，新內容已就位但舊檔暫名刪不掉者reject(ftpUpload: fpRemote is updated, but can not remove the old file kept under a temporary name in the same folder)。

    失敗訊息(固定詞彙，不含路徑與伺服器訊息)：傳輸本身之錯誤且暫存已清除時沿用原錯誤；暫存刪不掉者訊息後綴, can not remove the remote temporary file(傳輸錯誤改為ftpUpload: transfer failed (<code>), ...)；大小不符ftpUpload: uploaded size[N] does not match local size[M], fpRemote is not changed；本機檔改變ftpUpload: fpLocal was changed during upload, fpRemote is not changed；查不到暫存大小ftpUpload: can not get the size of the uploaded temporary file (<code>), fpRemote is not changed(FTP伺服器不支援SIZE者上傳一律如此)；交換退路中舊檔仍(或可能仍)以暫名保留者訊息含the old file of fpRemote is kept under a temporary name in the same folder(或may be kept)。

    逾時：建立資料夾、傳輸、核對大小、改名各階段分別以WFtp之opt.timeLimit計時(傳輸自開始起計，大檔須自行給較大值)，到時中止(銷毀本次所用之連線，FTP含數據socket，不再送出資料)、以同一設定重新連線(FTP重放曾成功之cwd)、刪除暫存後reject(ftpUploadCore timeout[timeLimit]；改名階段為ftpUploadCore timeout[timeLimit] while renaming, fpRemote may or may not be updated)；清理、還原與重新連線各步以min(timeLimit, 10000)毫秒為限。 中止會一併中斷同一實例上同時進行之其他操作(如併發之下載)；使用者已quit者不重新連線。控制連線於上傳開始前已中斷者，FTP先重新連線並重放cwd(失敗訊息見README之Connection behavior)；SFTP由伺服器斷線者沿用上傳之失敗處置(本次reject，其後實例重新連線)。行程崩潰或連線無法恢復而殘留之遠端暫存名不會自動清除。目標既有檔之權限與擁有者不保留(新檔依伺服器預設)；目標為符號連結者改由新檔取代該連結。

    改名: 傳輸端提供posixRename者先用之(原子覆蓋); 不支援或伺服器拒絕時改用rename; 仍被拒且fpRemote為既有檔案時(伺服器之rename不覆蓋), 依序把舊檔改為暫存名(<檔名>.<行程id>.<隨機碼>.old)、暫存改為fpRemote、刪除舊檔暫名(此退路非原子, 兩次改名之間fpRemote不存在); 交換中途失敗(含連線錯誤、逾時)之還原見restoreStep: fpRemote不存在即把舊檔改回; 連線層級之錯誤不退回其他改名方式(結果不明)

    逾時: 各階段(prepare: 建立遠端資料夾; transfer: 傳輸; verify: 查詢暫存大小; rename: 改名)各自以timeLimit計時, 到時呼叫adapter.abort()中止(銷毀該連線), 重新連線後清理, 再reject; 清理、還原與重新連線各步以min(timeLimit, 10000)為限; 任何失敗於reject前確認連線可用(必要時重新連線)

    opt.onTrace事件(type): 'timeout'({ timeLimit, stage: 'prepare'|'transfer'|'verify'|'rename'|'clean'|'reconnect' })、'transfer'({ ok, late })、'verify'({ ok, size, sizeLocal })、'temp'({ act: 'remove', ok, kind: 'part'|'old' })、'move'({ mode: 'posix'|'rename'|'swap' })、'reconnect'({ ok })由adapter發出; 逾時後之'transfer'(late為true)可能於promise已reject後才發生
